# Методика перевода Liminal Industries

## Назначение

Этот документ описывает единый повторяемый процесс перевода разных версий
модпака Liminal Industries.

В основе процесса лежат два независимых артефакта:

1. глобальный каталог утверждённых переводов, общий для всех версий модпака;
2. манифест конкретной версии, содержащий только тексты, обнаруженные в этой
   версии.

Глобальный каталог накапливает выполненные переводы и никогда не очищается.
Готовый переводческий мод, напротив, всегда собирается только для одной
конкретной версии модпака. В него нельзя включать строки только потому, что они
когда-либо встречались в другой версии.

Полный цикл выглядит так:

```text
английский оригинал целевой версии
  -> извлечение всех переводимых строк
  -> манифест версии
  -> сопоставление с глобальным каталогом
  -> дельта ещё не переведённых строк
  -> драфт перевода по единым критериям
  -> самопроверка автора и фиксация драфта
  -> независимое ревью
  -> исправление замечаний и утверждение редактором
  -> запись утверждённых переводов в каталог
  -> сборка ресурсов только по манифесту целевой версии
  -> тесты и JAR
```

Цель перевода не в буквальном соответствии английскому синтаксису. Текст
должен быть простым, коротким и легко понятным игроку. Это игра, а не
документация.

### Область применимости

Методика рассчитана на версии Liminal Industries на Forge с FTB Quests.
Версии Minecraft, Forge, FTB Quests и остальных модов могут различаться между
выпусками. Состав контентных модов также не считается постоянным: источником
истины всегда служит фактический состав целевой версии.

Перевод охватывает подключённые для конкретной версии источники:

- видимые тексты квестов FTB Quests;
- отображаемые названия зарегистрированных предметов;
- отображаемые названия зарегистрированных блоков;
- тексты книг Patchouli;
- текстовые руководства Immersive Engineering;
- книги на системе Mantle, включая Tinkers' Construct.

Точный список задаётся в `translation-versions/<version>/sources.json`.
Архитектура источников описана в `docs/TRANSLATION_SOURCES.md`.

KubeJS и ProbeJS являются ожидаемыми инструментами текущих версий, но не
инвариантами методики. Если в целевой версии они отсутствуют, изменили формат
данных или больше не дают полный реестр, извлекатель обязан использовать
другой воспроизводимый источник полного реестра и эффективных локализаций.
Замена источника не меняет правила формирования логических ID, каталога и
манифеста.

## Основные инварианты

1. Английский текст извлекается из точной целевой версии модпака.
2. Каждая переводимая строка имеет стабильный логический ID.
3. SHA-256 вычисляется от точного английского текста в UTF-8.
4. Перевод однозначно определяется парой `ID + source_hash`.
5. Изменившийся английский текст считается новой записью, даже если ID
   сохранился.
6. Утверждённые записи глобального каталога нельзя исправлять молча. Любая
   редакторская коррекция проходит тот же цикл драфта и независимого ревью,
   а её diff сохраняется как часть изменения.
7. В каталог можно добавлять новые записи и вносить утверждённые коррекции.
   Удалять исторические варианты `ID + source_hash` нельзя.
8. Агентам передаются только отсутствующие в каталоге пары
   `ID + source_hash`.
9. Одинаковый английский текст с другим ID не подставляется автоматически.
   Найденный перевод можно показать агенту как подсказку, но контекст должен
   быть проверен заново.
10. Ресурсы версии собираются пересечением её манифеста с каталогом, а не
    выгрузкой всего каталога.
11. Штатные русские локализации предметов и блоков не копируются в каталог и
    не включаются в переводческий мод.
12. Для книжного источника с `review_native: true` штатный `ru_ru` считается
    только неутверждённым драфтом: его можно передать на ревью, но нельзя
    автоматически записать в каталог или payload.
13. Точная утверждённая пара `ID + source_hash` всегда получает статус
    `FINALIZED` раньше проверки штатного `ru_ru`. Флаг `review_native` и
    изменение только штатного русского текста не могут повторно открыть такую
    запись для ревью.
14. Новый `source_hash` английского оригинала создаёт новую проверяемую запись,
    даже если логический ID и штатный русский текст не изменились.
15. Существующие `ru_ru` модпака не переопределяются без необходимости.
    Отсутствующая, невалидная, структурно устаревшая или не прошедшая критерии
    приёмки книга является достаточной причиной для версионного переопределения.
16. Структурная актуальность определяется для страницы или статьи целиком до
    создания строк дельты. Все её записи получают один статус. Штатный текст
    из `STALE_NATIVE` не используется как подсказка, поскольку соответствие
    смещённых строк или элементов массива не доказано.

## Рабочие каталоги

```sh
TRANSLATION_REPO="$HOME/Documents/minecraft-industrial-backrooms"
MODPACK_ROOT="$HOME/Projects/minecraft-industrial-backrooms"
LAUNCHER_ROOT="$HOME/Library/Application Support/sklauncher"
```

Роли каталогов:

- `TRANSLATION_REPO` хранит каталог переводов, манифесты версий, дельты,
  утилиты, исходники переводческого мода и собранные ресурсы;
- `MODPACK_ROOT` хранит точную распакованную целевую версию модпака;
- `LAUNCHER_ROOT` используется для проверки наличия штатной локализации
  Minecraft.

Не полагайся на эти пути вслепую. В начале работы найди каталоги, подтверди
версию модпака и выполни:

```sh
cd "$TRANSLATION_REPO"
git status --short
```

Не отменяй и не включай в свою работу чужие незавершённые изменения.

## Структура данных

### Глобальный каталог

Канонический каталог хранится в репозитории отдельно от результатов сборки:

```text
translation-catalog/catalog.json
```

Логическая структура каталога:

```json
{
  "schema_version": 1,
  "entries": {
    "quest:0123456789abcdef:title": [
      {
        "source_hash": "sha256:7f...",
        "source": "Getting Started",
        "translation": "Начало работы"
      },
      {
        "source_hash": "sha256:31...",
        "source": "A New Beginning",
        "translation": "Новое начало"
      }
    ],
    "quest:0123456789abcdef:description:0": [
      {
        "source_hash": "sha256:a2...",
        "source": "Find a way out.",
        "translation": "Найдите выход."
      }
    ],
    "item:block.refurbished_furniture.plate": [
      {
        "source_hash": "sha256:53...",
        "source": "Plate",
        "translation": "Тарелка"
      }
    ]
  }
}
```

Массив позволяет одному логическому ID иметь несколько английских
формулировок из разных версий модпака. Внутри массива не может быть двух
записей с одинаковым `source_hash`.

`source` хранится обязательно. Хеш нужен для надёжного сопоставления, а
исходная формулировка — для ревью, диагностики и защиты от ошибочного
сопоставления.

Неизменяемость относится к содержимому уже существующих записей. Утилита
добавления может переформатировать JSON, но обязана доказать, что все прежние
объекты сохранились без логических изменений.

Пока каталог полностью неизменяем. Если после публикации обнаружена ошибка,
не редактируй запись самовольно и не создавай вторую запись с той же парой
`ID + source_hash`. Такой случай требует отдельного изменения формата и
политики ревизий.

### Логические ID

Используются следующие ID:

```text
quest:<quest_id>:title
quest:<quest_id>:subtitle
quest:<quest_id>:description:<index>
quest-group:<group_id>:title
quest-chapter:<chapter_id>:title
quest-task:<quest_id>:<task_id>:title
quest-reward:<quest_id>:<reward_id>:title
item:<translation_key>
block:<translation_key>
patchouli-lang:<namespace>:<key_or_hash>
patchouli-json:<namespace>:<book>:<path>:<json_pointer>
mantle-book:<namespace>:<book>:<path>:<json_pointer>
mantle-book-language:<namespace>:<book>:<key>
```

`quest-chapter`, `quest-task` и `quest-reward` используются для видимых
заголовков, которые FTB Quests хранит вне основных текстовых полей квеста.
ID родительского квеста включается в ID задачи или награды, поэтому локальные
ID вложенных объектов не создают коллизий между квестами.

Если извлекатель обнаруживает другой переводимый тип поля, для него сначала
задаётся однозначная схема ID, и только после этого поле допускается в
каталог.

Индекс строки описания считается частью позиции поля в структурно разобранном
SNBT. Пустые строки тоже учитываются при вычислении позиции, даже если сами не
переводятся. Нельзя получать ID регулярным выражением или номером строки
файла.

### Хеш английского оригинала

Хеш вычисляется так:

```python
hashlib.sha256(source.encode("utf-8")).hexdigest()
```

Перед вычислением нельзя:

- обрезать пробелы;
- менять регистр;
- нормализовать Unicode;
- заменять переводы строк;
- удалять коды форматирования;
- изменять подстановки или разметку.

Любое видимое или служебно значимое изменение оригинала должно дать новый
хеш и потребовать проверки перевода.

### Манифест версии

Для каждого выпуска создаётся отдельный воспроизводимый манифест:

```text
translation-versions/<version>/manifest.json
```

Он содержит:

- точную идентификацию модпака, Minecraft, Forge и FTB Quests;
- фактический список установленных модов и их версий;
- путь и SHA-256 каждого исходного файла;
- все извлечённые английские записи;
- их логические ID, типы, расположение и `source_hash`;
- сведения, необходимые для обратной упаковки;
- `source_id`, `source_type` и формат результата;
- для записей lang — эффективный translation key и namespace;
- для Patchouli JSON — архив, resource path и JSON pointer;
- отметку о штатном покрытии `ru_ru`, но не сам штатный русский текст.

Манифест является снимком английского оригинала конкретной версии и не
является частью глобального каталога. Для источника с `review_native: true`
он может дополнительно содержать `native_translation`, её происхождение и
результат структурной проверки. Это недоверенный материал для ревью, а не
утверждённый перевод.

Пример записи:

```json
{
  "id": "quest:0123456789abcdef:description:0",
  "kind": "quest_description",
  "source": "Find a way out.",
  "source_hash": "sha256:a2...",
  "location": {
    "file": "chapters/sector_1.snbt",
    "quest_id": "0123456789abcdef",
    "field": "description",
    "index": 0
  }
}
```

Для предмета:

```json
{
  "id": "item:block.refurbished_furniture.plate",
  "kind": "item_name",
  "source": "Plate",
  "source_hash": "sha256:53...",
  "namespace": "refurbished_furniture",
  "translation_key": "block.refurbished_furniture.plate",
  "native_ru_present": false
}
```

Для обычного источника поле `native_ru_present` используется только для того,
чтобы не создавать ненужное переопределение. Для книжного источника с
`review_native: true` наличие штатного текста не закрывает запись: он
передаётся в дельту как `native_translation`, пока точная пара
`ID + source_hash` не утверждена в каталоге.

### Дельта перевода

Дельта — временный рабочий набор:

```text
translation-versions/<version>/work/pending.tsv
```

В неё попадают только записи, которые:

- присутствуют в манифесте целевой версии;
- требуют собственного перевода;
- не имеют точного совпадения `ID + source_hash` в каталоге.

Для предметов запись со штатным `ru_ru` не требует собственного перевода и в
дельту не попадает. Для квестов перевод требуется всегда. Для книг с
`review_native: true` в дельту попадают отсутствующие, невалидные,
структурно устаревшие и ещё не проверенные штатные переводы.

## Источники истины

Используй источники в следующем порядке:

1. точные английские файлы целевой версии модпака;
2. эффективный `en_us` после всех переопределений, включая KubeJS, когда он
   присутствует;
3. глобальный каталог для точной пары `ID + source_hash`;
4. утверждённый глоссарий;
5. редакторское решение для новой строки.

Штатные `ru_ru` Minecraft и модов не становятся утверждёнными записями
глобального каталога автоматически. Для предметов и блоков их разрешается
проверять только для ответа на вопрос, нужно ли создавать собственное
переопределение translation key. Такой текст:

- не копируется в каталог;
- не передаётся агентам как утверждённый перевод;
- не записывается в payload выбранной версии;
- не изменяется переводческим модом.

Для источника с `review_native: true` штатный книжный текст разрешается
передать как подсказку и исходный драфт только после успешной проверки
структуры всего ресурса. Он проходит те же девять критериев, самопроверку и
независимое ревью, что и новый перевод. Только после `APPROVED` он записывается
в каталог и может попасть в payload.

Основные документы:

```text
QUEST_GLOSSARY.md
QUEST_GLOSSARY.tsv
TRANSLATION_METHODOLOGY.md
docs/QUEST_TRANSLATION.md
docs/ITEM_TRANSLATION.md
docs/UPDATING.md
docs/PACKAGING.md
```

При расхождении старых документов с этой методикой правила каталога и сборки
из манифеста имеют приоритет.

## Обычный цикл перевода новой версии

### 1. Подтверждение версии

Зафиксируй:

- название и номер версии модпака;
- CurseForge file ID или другой идентификатор дистрибутива;
- версию Minecraft, Forge и FTB Quests;
- фактический список установленных модов и их версий;
- SHA-256 исходного архива, если он доступен.

Не используй уже переведённый
`translation-versions/<version>/payload/quests` как английский источник.

### 2. Извлечение

Запусти единый извлекатель версии. Он должен:

1. структурно прочитать английские SNBT;
2. получить полный реестр предметов и их эффективные translation keys;
3. разрешить эффективные `en_us`;
4. вычислить логические ID и хеши;
5. проверить только наличие штатного `ru_ru` для предметов и блоков;
6. для книг с `review_native: true` извлечь английскую структуру, проверить
   наличие, синтаксис и структурную актуальность штатного `ru_ru`;
7. создать детерминированный `manifest.json`.

Извлекатель не должен читать глобальный каталог и не должен создавать
русские файлы. Одинаковый вход обязан давать байт-в-байт одинаковый манифест.

### 3. Вычисление дельты

Сопоставь манифест с каталогом.

Результат должен разделять записи на:

- `FINALIZED` — точная пара `ID + source_hash` уже утверждена;
- `NATIVE_RU` — предмет уже покрыт штатной русской локализацией;
- `REVIEW_NATIVE` — штатный книжный перевод существует, но ещё не утверждён;
- `MISSING_NATIVE` — русской строки или страницы нет;
- `INVALID_NATIVE` — русский ресурс не разбирается штатным форматом;
- `STALE_NATIVE` — русский ресурс не соответствует английской структуре;
- `PENDING` — требуется новый перевод;
- `ERROR` — неоднозначный ID, конфликт хеша, отсутствующий английский текст
  или другая структурная ошибка.

В рабочую дельту попадают `PENDING`, `REVIEW_NATIVE`, `MISSING_NATIVE`,
`INVALID_NATIVE` и `STALE_NATIVE`. `FINALIZED` никогда не попадает в неё
повторно. При наличии `ERROR` работа останавливается.

Для удобства агенту можно приложить:

- другие формулировки того же ID из каталога;
- переводы такого же `source_hash` под другими ID;
- соседние строки квеста или семейство предметов.

Эти данные являются контекстом, но не считаются автоматическим совпадением.

### 4. Обновление глоссария

До параллельного перевода:

1. просмотри новые и изменившиеся названия;
2. найди повторяющиеся предметы, машины, материалы и измерения;
3. сверь решения с интерфейсом целевой версии;
4. обнови `QUEST_GLOSSARY.md` и `QUEST_GLOSSARY.tsv`;
5. передай компактный TSV каждому переводчику и редактору.

Имена модов и брендов не переводятся: `Create`, `AE2`, `Botania`,
`Mekanism`, `Ender IO`, `JEI`, `KubeJS`, `FTB Quests`.

### 5. Подготовка драфта

Каждая партия перевода проходит одну и ту же последовательность независимо от
типа текста:

```text
PENDING, REVIEW_NATIVE, MISSING_NATIVE, INVALID_NATIVE, STALE_NATIVE
или утверждённая заявка на коррекцию
  -> DRAFT
  -> AUTHOR_CHECKED
  -> IN_REVIEW
  -> CHANGES_REQUESTED или APPROVED
  -> исправление замечаний
  -> повторное подтверждение редактором
  -> запись в каталог
```

Разделяй квесты по целым главам, а предметы — по namespace и семействам. Не
дроби связный контекст между агентами. Книгу передавай целиком или цельными
разделами с соседними страницами.

Перед началом драфта координатор:

1. фиксирует точный набор `ID + source_hash`;
2. прикладывает английский оригинал, соседний контекст и актуальный глоссарий;
3. показывает утверждённые UI-названия упомянутых предметов;
4. отмечает ограничения формата: длину поля, страницу книги, подстановки и
   управляющую разметку;
5. назначает автора и отдельного редактора.

Автор готовит драфт и проверяет каждую строку по обязательным критериям:

1. **Точность.** Сохранены действие, условие, результат, предупреждение,
   отрицание, количество и причинно-следственная связь.
2. **Естественный русский.** Нет кальки, английского порядка слов, лишних
   местоимений, ложных друзей переводчика и неуместной английской
   капитализации.
3. **Простой игровой язык.** Короткие предложения, знакомые слова и прямые
   команды предпочтительнее канцелярита и документального стиля.
4. **Терминология.** Названия совпадают с `QUEST_GLOSSARY.tsv`, JEI,
   интерфейсом целевой версии и другими уже утверждёнными текстами.
5. **Связность.** Строка читается вместе с заголовком, соседними страницами,
   задачами, наградами и подписями, а не только сама по себе.
6. **Тон.** Инструкция остаётся практичной, художественный фрагмент сохраняет
   атмосферу, а шутка не превращается в буквальный бессмысленный перевод.
7. **Краткость и вместимость.** Убраны повторы и слова без новой информации;
   текст рассчитан на реальный экран, страницу книги, кнопку или подсказку.
8. **Техническая целостность.** Сохранены ID, числа, ссылки, форматирование,
   плейсхолдеры, команды, NBT и разметка.
9. **Полнота.** Переведены все назначенные видимые поля; не осталось случайных
   английских фрагментов.

Базовая инструкция:

```text
Переведи только назначенные записи PENDING с английского на простой,
естественный русский язык для игры.

Правила:
1. Не изменяй id, source_hash, source и количество записей.
2. Заполняй только translation.
3. Сохраняй &- и §-коды, %s, %d, {image:...}, команды, NBT и namespace:id.
4. Используй QUEST_GLOSSARY.tsv.
5. Не переводи бренды, названия модов и технические сокращения.
6. Не добавляй сведений, которых нет в оригинале.
7. Избегай буквальных калек, английского порядка слов и канцелярита.
8. Проверяй перевод вместе с соседними строками, а не изолированно.
9. Сокращай фразу, если это не меняет смысл.
10. Не редактируй глобальный каталог и файлы других исполнителей.
```

После перевода автор выполняет самопроверку по девяти критериям, исправляет
найденное и фиксирует драфт. Самопроверка автора обязательна, но не заменяет
независимое ревью. Координатор не добавляет частичный или непроверенный
результат в каталог.

### 6. Независимое ревью

Автор не может быть единственным редактором собственного участка. Независимое
ревью выполняет другой человек или отдельный агент без опоры на рассуждения
автора. Редактор получает оригинал, зафиксированный драфт, контекст, глоссарий
и UI-названия. Первый проход проводится без изменения файлов: редактор
возвращает замечания, а не переписывает драфт молча.

Редактор повторно применяет все девять критериев драфта и дополнительно
проверяет:

- естественность текста при чтении вслух;
- единый голос и обращение во всём связанном участке;
- отсутствие формально правильных, но неигровых формулировок;
- соответствие заголовка содержанию, а подписи — изображению или рецепту;
- отсутствие одиноких подписей, пустых страниц и ссылок на удалённые рецепты;
- для `block_name` — буквальное совпадение с уже утверждённым `item_name`,
  если `block_id` и `item_id` обозначают один registry-объект; ошибочную
  item-запись сначала исправляют отдельной утверждённой коррекцией, а не
  обходят новым вариантом перевода блока;
- форматирование, подстановки и технические фрагменты;
- точность ID, `source_hash` и числа записей.

Формат замечания:

```text
ID, source_hash, текущий перевод, рекомендуемый перевод, краткая причина
```

Координатор разрешает каждое замечание: принимает правку либо записывает
обоснованный отказ. Автор обновляет драфт, после чего редактор проверяет
изменённые места и явно выставляет `APPROVED`. Наличие незакрытого замечания
или отсутствие подтверждения редактора блокирует запись в каталог.

#### Особенности разных поверхностей

- **Квесты:** читать целую главу; проверять последовательность действий,
  условия задач, награды, зависимости и одинаковое обращение к игроку.
- **Книги:** читать страницы подряд; проверять переходы между разворотами,
  подписи, изображения, рецепты, ссылки, плотность текста и фактическое
  отображение в игре. Ссылки на рецепты проверять по эффективному runtime-набору
  после применения KubeJS и datapack, а не только по содержимому JAR мода.
- **Названия:** проверять семейство целиком; использовать краткое UI-имя без
  пояснений, соблюдать число и тип объекта, сверять одинаковые registry-объекты
  во всех источниках.

#### Дефекты исходных книг

Перевод книги включает проверку работоспособности её страниц в точной целевой
версии модпака. Для каждой страницы с рецептом, предметом, изображением,
внутренней ссылкой или нестандартным типом:

1. проверь существование указанного ID или ресурса в эффективном runtime;
2. учти удаления и замены, выполненные KubeJS, datapack и конфигурацией сборки;
3. найди в журнале Patchouli предупреждения `recipe not found`, ошибки ресурсов
   и неизвестные типы страниц;
4. открой страницу в игре и убедись, что основной элемент действительно
   отображается, а подпись не осталась одна на пустом развороте.

Проверка распространяется и на штатный русский ресурс:

1. отсутствующая русская страница даёт `MISSING_NATIVE`;
2. ошибка синтаксического разбора даёт `INVALID_NATIVE`;
3. отсутствующее поле, строка или обязательный управляющий маркер даёт
   `STALE_NATIVE`;
   для JSON также сравниваются типы, длины массивов и все технические значения,
   а для TXT — управляющие маркеры каждой соответствующей строки;
4. структурно актуальный текст без каталожного утверждения даёт
   `REVIEW_NATIVE`;
5. точное совпадение с каталогом по `ID + source_hash` даёт `FINALIZED`
   независимо от состояния штатного `ru_ru`.

Невалидный или устаревший русский файл не ремонтируется строковыми заменами.
Сборщик берёт валидную английскую структуру как шаблон, заменяет только
извлечённые видимые поля утверждёнными переводами и повторно сериализует
ресурс. Registry ID, пути изображений, рецепты, фильтры, операции индекса и
прочие технические поля переносятся из английского оригинала без перевода.

Изменение `native_translation` после утверждения фиксируется как диагностическая
информация об upstream-ресурсе, но не инвалидирует `FINALIZED`. Повторное ревью
нужно только при новом английском `source_hash` или при явно оформленной
редакторской коррекции нашей записи.

Если исходная книга ссылается на удалённый или динамически созданный рецепт:

1. не маскируй проблему переводом подписи и не выдумывай стабильный ID;
2. зафиксируй исходный ID, runtime-предупреждение и причину расхождения;
3. создай минимальное версионное переопределение страницы в
   `translation-versions/<version>/resourcepack-overrides`;
4. укажи новый стабильный ID, если он достоверно известен;
5. если стабильного ID нет, замени сломанную страницу на полезную карточку
   предмета или краткое пояснение с указанием посмотреть актуальный рецепт в
   JEI;
6. не меняй соседние рабочие страницы и английский ресурс исходного мода;
7. передай структурное исправление тому же независимому редактору и повторно
   проверь страницу в игре.

Такое переопределение считается исправлением совместимости конкретной версии,
а не вольной правкой перевода. Оно должно храниться отдельно от генерируемого
`payload` и накладываться сборщиком воспроизводимо.

### 7. Утверждение и запись в каталог

После завершения драфта и независимого ревью используй только специальную
операцию записи. Она обязана:

1. проверить соответствие каждой записи актуальному манифесту;
2. отклонить изменённые `id`, `source` и `source_hash`;
3. отклонить пустые переводы;
4. для новой пары отклонить уже существующий `ID + source_hash`;
5. для коррекции потребовать старый перевод, новый перевод, причину и
   подтверждение независимого редактора;
6. отклонить изменения записей, не входящих в утверждённую партию;
7. добавить или скорректировать только утверждённые записи;
8. записать детерминированный каталог;
9. повторным запуском подтвердить отсутствие новых изменений.

Нельзя редактировать `catalog.json` вручную.

### 8. Сборка целевой версии

Сборщик получает:

```text
manifest.json + catalog.json + английские файлы целевой версии
```

Для каждой записи манифеста он:

1. находит точную пару `ID + source_hash`;
2. подставляет утверждённый перевод;
3. пропускает предметы со штатным `ru_ru`;
4. выдаёт ошибку, если обязательный перевод отсутствует.

Сборщик не имеет права перебирать каталог и выгружать все известные записи.
Направление обхода всегда такое:

```text
манифест целевой версии -> точный поиск в каталоге -> выходной ресурс
```

Результат:

```text
translation-versions/<version>/payload/quests/
translation-versions/<version>/payload/resourcepack/assets/<namespace>/lang/ru_ru.json
```

В `payload/quests` попадает полный структурный набор квестов целевой версии с
переведёнными видимыми полями. Payload каждой версии хранится отдельно и не
переключает общий каталог исходников.

В собственные `ru_ru.json` попадают только translation keys, которым нужен
перевод проекта в этой версии. Штатные русские строки Minecraft и модов не
копируются и не переопределяются.

Удалённые из целевой версии квесты и предметы исчезают из собранных ресурсов,
но навсегда остаются в глобальном каталоге.

## Правила перевода

### Тон

- Пиши так, как обычно пишут в игровом интерфейсе.
- Используй короткие предложения и знакомые слова.
- Отдавай предпочтение действию: `Положите`, `Соедините`, `Найдите`.
- Не имитируй английский порядок слов.
- Не усложняй фразу ради технической точности, которая игроку не нужна.
- Сохраняй атмосферный тон художественного текста.
- Не переноси английскую капитализацию каждого слова в русский текст.

### Терминология

- Одному объекту в рамках версии соответствует одно русское UI-имя.
- Совпадающие `block_id` и `item_id` считаются одним UI-объектом. При
  утверждении `block_name` его перевод автоматически сверяется с точной
  item-записью текущей версии в неизменяемом каталоге.
- Сначала определяется название предмета, затем оно используется в квестах.
- Используй официальные термины Minecraft: `редстоун`, `скалк`, `Незер`,
  `Энд`, `эндерняк`, `тихоня`, `лавомерка`.
- Сохраняй принятые сокращения: `ME`, `P2P`, `FE`, `RF`, `NBT`.
- `Backrooms` и `Poolrooms` являются собственными именами.
- Намеренно оставлены `Ars Ecclesia`, `"Enderios"`, `Snad` и `Suol Snad`.

### Что нельзя менять

- ID квестов, предметов и translation keys;
- структуру SNBT, зависимости, задачи и награды;
- `namespace:path`, команды, NBT, координаты и имена файлов;
- коды форматирования `&o`, `&l`, `&6`, `§6`;
- подстановки `%s`, `%d` и разметку `{image:...}`;
- английский оригинал и его `source_hash`.

## Проверки

### Проверка каталога

- JSON соответствует схеме;
- каждый хеш совпадает с сохранённым `source`;
- нет дубликатов `ID + source_hash`;
- все значения `source` и `translation` непустые;
- исторические варианты не удалены;
- изменения существующих переводов ограничены утверждённой коррекцией;
- повторное добавление той же дельты ничего не меняет.

### Проверка покрытия версии

Для каждой записи манифеста должен существовать ровно один допустимый исход:

```text
точный перевод из каталога
или
штатное ru_ru для источника без review_native
```

Ни одна запись другой версии не должна попасть в результат.

Отчёт сборки обязан показывать:

```text
всего английских записей
совпадений с каталогом
штатно покрытых предметов
новых переводов
отсутствующих переводов
выходных квестовых строк
выходных item translation keys
```

Готовность требует `PENDING = 0`, `ERROR = 0` и отсутствия неиспользованных
ключей в собранном ресурс-паке.

### Структурная проверка квестов

- набор файлов, квестов и групп совпадает с английским оригиналом версии;
- изменены только переводимые поля;
- сохранено число элементов описаний, включая пустые;
- сохранены ID, зависимости, задачи, награды и форматирование;
- исходные SHA-256 соответствуют манифесту.

### Проверка книг

- все страницы прочитаны в порядке отображения, а не как изолированные строки;
- для штатных книг проверены наличие, синтаксис и соответствие английской
  структуре;
- для книг Mantle отдельно сопоставлены все пары `key=value` в
  `language.lang`; отсутствие русского значения считается дефектом, даже если
  JSON-страницы книги полностью переведены;
- технические и пробельные строки не создают заданий на перевод, а
  `native_translation` присутствует только у структурно актуального ресурса;
- `FINALIZED` вычисляется до статусов штатного перевода и не возвращается в
  дельту при повторном сканировании;
- невалидные и устаревшие русские ресурсы восстановлены из английской
  структуры, а не исправлены ненадёжными текстовыми заменами;
- recipe ID разрешаются после применения KubeJS и datapack целевой версии;
- item ID, изображения, внутренние ссылки и нестандартные типы страниц
  существуют;
- в журнале нет относящихся к переведённым страницам `recipe not found` и
  ошибок загрузки ресурсов;
- нет пустых разворотов, одиноких подписей и элементов, потерявших контекст;
- версионные исправления находятся в `resourcepack-overrides`, воспроизводимо
  попадают в `payload` и прошли независимое ревью;
- длина текста, разметка и переходы проверены непосредственно в игре.

### Проверка предметов

- полнота реестра подтверждена для целевой версии;
- ProbeJS используется, когда он доступен и содержит полный реестр; в
  остальных случаях используется другой воспроизводимый источник;
- проверяются не только `item.*`, но также `block.*`, `fluid.*`,
  `fluid_type.*` и `entity.*`;
- собственный ресурс-пак не содержит ключей со штатным `ru_ru`;
- все JSON корректны;
- один translation key имеет не более одного выходного значения;
- названия предметов совпадают с формулировками квестов и глоссарием.

### Тесты и сборка

```sh
cd "$TRANSLATION_REPO/mod"
./gradlew clean test build
```

Тесты должны дополнительно проверять, что встроенные ресурсы получены из
одного манифеста версии и не содержат записей каталога, отсутствующих в этом
манифесте.

### Обязательная установка после завершения перевода

Работа над переводом не считается завершённой после сборки одного релизного
JAR. Для той же `translationVersion` обязательно:

1. собрать релизный мод перевода;
2. собрать отдельный мод из `audit-mod/`;
3. скопировать оба полученных JAR в каталог `mods` соответствующего
   SK Launcher-инстанса;
4. убедиться, что в инстансе не осталось другой версии этих двух модов.

Соответствие поддерживаемых версий:

| `translationVersion` | SK Launcher-инстанс |
| --- | --- |
| `1.19.3-original` | `liminal-industries` |
| `1.19.3-7-ae2-fix` | `liminal-industries-rescripted` |

Пример полного финального шага из корня репозитория:

```sh
VERSION=1.19.3-7-ae2-fix
INSTANCE="$HOME/Library/Application Support/sklauncher/instances/liminal-industries-rescripted"

./mod/gradlew -p mod clean test build -PtranslationVersion="$VERSION"
./mod/gradlew -p audit-mod clean test build -PtranslationVersion="$VERSION"

cp -f \
  "mod/build/libs/liminal-industries-russian-translation-$VERSION.jar" \
  "$INSTANCE/mods/"
cp -f \
  "audit-mod/build/libs/liminal-industries-russian-translation-audit-$VERSION.jar" \
  "$INSTANCE/mods/"
```

Для `1.19.3-original` в `VERSION` и `INSTANCE` подставляются значения из
таблицы. Audit-мод является служебным: он устанавливается в локальный инстанс
для проверки, но не включается в публикуемый JAR и не распространяется как
часть релиза.

## Автоматическая проверка в игре

Статический манифест не заменяет проверку фактического runtime-реестра.
Собери отдельный служебный мод из `audit-mod/`, установи его рядом с релизным
JAR в чистый профиль точной версии, выбери `ru_ru`, войди в мир и после полной
загрузки JEI выполни:

```text
/liminal_ru_audit
```

Проверка должна завершиться `PASS`. Отчёт
`liminal-industries-ru-audit/item-name-audit.json` охватывает все реальные
варианты `ItemStack` из JEI и базовые стеки runtime-реестра. Английский
fallback не считается русским переводом. Служебный мод и его зависимость от
JEI запрещено включать в публикуемый JAR перевода.

## Ручная проверка в игре

После успешного автоматического аудита визуально проверь:

1. при `ru_ru` переведены названия глав, квестов и описания;
2. при другом языке отображается оригинальный текст;
3. смена языка не изменяет файлы квестов;
4. перевод работает на сервере без переводческого мода;
5. названия предметов помещаются и корректно отображаются в JEI;
6. штатные русские названия Minecraft и модов сохранились;
7. награды и требования используют те же названия, что JEI;
8. длинные названия и описания помещаются в интерфейсе;
9. форматирование, изображения и подстановки не сломаны;
10. в журнале нет сообщения о несовместимом наборе ID.

## Частые ошибки

- Выгружать в мод весь глобальный каталог вместо записей целевой версии.
- Считать совпадение только по ID и не проверять хеш оригинала.
- Автоматически переносить перевод одинакового текста между разными ID.
- Нормализовать английский текст перед хешированием.
- Исправлять старую запись каталога без отдельного драфта, независимого ревью
  и зафиксированного diff.
- Добавлять в каталог перевод до завершения независимого ревью.
- Импортировать штатные `ru_ru` Minecraft или модов в каталог.
- Копировать штатные русские строки в собственный ресурс-пак.
- Извлекать английский текст из уже переведённых SNBT.
- Переводить только предметы, упомянутые в квестах.
- Искать только ключи `item.*`.
- Слепо переводить ID с подчёркиваниями как отображаемое имя.
- Переводить подпись к сломанному рецепту, не проверив, отображается ли сам
  рецепт после изменений KubeJS.
- Подменять удалённый рецепт выдуманным ID вместо версионного исправления
  страницы с зафиксированной причиной.
- Запаковывать частичную дельту.
- Сохранять удалённые строки старой версии в новом JAR.
- Включать в коммит чужие незавершённые изменения.

## Итоговый чек-лист координатора

- [ ] Точная версия модпака подтверждена.
- [ ] Английский оригинал извлечён в отдельный манифест.
- [ ] Манифест воспроизводим и содержит хеши исходных файлов.
- [ ] Полный реестр предметов получен из ProbeJS или другого
      воспроизводимого источника и проверен на полноту.
- [ ] Выполнено точное сопоставление `ID + source_hash` с каталогом.
- [ ] Штатные `ru_ru` предметов и блоков только учтены как покрытие.
- [ ] Штатные книги с `review_native: true` классифицированы как
      `REVIEW_NATIVE`, `MISSING_NATIVE`, `INVALID_NATIVE` или `STALE_NATIVE`.
- [ ] Утверждённые `ID + source_hash` получили `FINALIZED` и не вернулись в
      дельту.
- [ ] Агентам переданы только записи из рабочей дельты, но не `FINALIZED`.
- [ ] Глоссарий обновлён до начала параллельного перевода.
- [ ] Автор выполнил самопроверку драфта по девяти критериям.
- [ ] Другой человек или агент выполнил независимое ревью по тем же критериям.
- [ ] Редактор явно подтвердил итоговый вариант.
- [ ] Все замечания разрешены до добавления записей в каталог.
- [ ] В каталог добавлены только новые записи и утверждённые коррекции.
- [ ] Остальная часть каталога не изменилась.
- [ ] Повторный запуск добавления идемпотентен.
- [ ] `PENDING = 0` и `ERROR = 0`.
- [ ] Ресурсы собраны обходом манифеста целевой версии.
- [ ] В результате нет строк из других версий.
- [ ] В собственном ресурс-паке нет штатно переведённых ключей.
- [ ] Квесты, глоссарий и UI используют одинаковые названия.
- [ ] Все страницы переведённых книг проверены на эффективных runtime-ресурсах.
- [ ] В книгах нет пустых страниц, одиноких подписей и ссылок на удалённые
      рецепты.
- [ ] Версионные исправления книг прошли независимое ревью и сборку из
      `resourcepack-overrides`.
- [ ] `./gradlew clean test build` проходит.
- [ ] Audit-мод собран для той же `translationVersion`, что и релизный JAR.
- [ ] Оба JAR скопированы в `mods` соответствующего SK Launcher-инстанса, а
      другие версии этих модов удалены.
- [ ] `/liminal_ru_audit` в обновлённом инстансе завершился `PASS`.
- [ ] JAR проверен в игре на русском и другом языке.

## Стартовая инструкция для чистой сессии

```text
Работай как координатор перевода Liminal Industries.

Сначала прочитай TRANSLATION_METHODOLOGY.md, QUEST_GLOSSARY.md,
QUEST_GLOSSARY.tsv и документы из docs/. Найди точную распакованную целевую
версию модпака и проверь git status. Не трогай чужие изменения.

Выполни цикл:
1. извлеки из английского оригинала все строки квестов и полный реестр
   предметов в манифест версии;
2. вычисли точные SHA-256 без нормализации;
3. сопоставь записи с глобальным каталогом по ID + source_hash;
4. штатные ru_ru предметов используй только как покрытие, а штатные книги с
   review_native классифицируй и передай как неутверждённый драфт;
5. сначала исключи FINALIZED, затем передай агентам только рабочие статусы
   дельты или явно утверждённые заявки на коррекцию;
6. подготовь драфт и выполни авторскую самопроверку по девяти критериям;
7. передай зафиксированный драфт другому агенту на независимое ревью по тем же
   критериям и добейся явного APPROVED;
8. добавь новые переводы или утверждённые коррекции в каталог, не меняя
   остальных записей;
9. собери квесты и собственные ru_ru только обходом манифеста этой версии;
10. добейся PENDING = 0 и ERROR = 0;
11. запусти тесты и собери релизный JAR;
12. для той же translationVersion собери audit-mod, скопируй оба JAR в mods
    соответствующего SK Launcher-инстанса и удали из него другие версии этих
    модов;
13. после перезапуска клиента выполни /liminal_ru_audit и сообщи точные
    результаты сборки, установки и runtime-аудита.

Никогда не собирай мод прямой выгрузкой всего глобального каталога.
```
