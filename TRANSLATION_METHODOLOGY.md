# Методика перевода Liminal Industries

## Назначение

Этот документ описывает единый повторяемый процесс перевода разных версий
модпака Liminal Industries.

В основе процесса лежат два независимых артефакта:

1. глобальный каталог утверждённых переводов, общий для всех версий модпака;
2. манифест конкретной версии, содержащий только тексты, обнаруженные в этой
   версии.

Глобальный каталог накапливает выполненные переводы и никогда не очищается.
Готовый переводческий мод, напротив, всегда собирается только для одной
конкретной версии модпака. В него нельзя включать строки только потому, что они
когда-либо встречались в другой версии.

Полный цикл выглядит так:

```text
английский оригинал целевой версии
  -> извлечение всех переводимых строк
  -> манифест версии
  -> сопоставление с глобальным каталогом
  -> дельта ещё не переведённых строк
  -> перевод
  -> независимое ревью
  -> добавление утверждённых переводов в каталог
  -> сборка ресурсов только по манифесту целевой версии
  -> тесты и JAR
```

Цель перевода не в буквальном соответствии английскому синтаксису. Текст
должен быть простым, коротким и легко понятным игроку. Это игра, а не
документация.

### Область применимости

Методика рассчитана на версии Liminal Industries на Forge с FTB Quests.
Версии Minecraft, Forge, FTB Quests и остальных модов могут различаться между
выпусками. Состав контентных модов также не считается постоянным: источником
истины всегда служит фактический состав целевой версии.

Перевод охватывает два класса текста:

- видимые тексты квестов FTB Quests;
- отображаемые названия зарегистрированных предметов независимо от префикса
  их translation key.

KubeJS и ProbeJS являются ожидаемыми инструментами текущих версий, но не
инвариантами методики. Если в целевой версии они отсутствуют, изменили формат
данных или больше не дают полный реестр, извлекатель обязан использовать
другой воспроизводимый источник полного реестра и эффективных локализаций.
Замена источника не меняет правила формирования логических ID, каталога и
манифеста.

## Основные инварианты

1. Английский текст извлекается из точной целевой версии модпака.
2. Каждая переводимая строка имеет стабильный логический ID.
3. SHA-256 вычисляется от точного английского текста в UTF-8.
4. Перевод однозначно определяется парой `ID + source_hash`.
5. Изменившийся английский текст считается новой записью, даже если ID
   сохранился.
6. Старые записи глобального каталога неизменяемы: их нельзя исправлять,
   заменять или удалять.
7. Новые записи можно только добавлять.
8. Агентам передаются только отсутствующие в каталоге пары
   `ID + source_hash`.
9. Одинаковый английский текст с другим ID не подставляется автоматически.
   Найденный перевод можно показать агенту как подсказку, но контекст должен
   быть проверен заново.
10. Ресурсы версии собираются пересечением её манифеста с каталогом, а не
    выгрузкой всего каталога.
11. Штатные русские локализации Minecraft и установленных модов не копируются
    в каталог и не включаются в переводческий мод.
12. Существующие `ru_ru` модпака не изменяются и не переопределяются без
    необходимости.

## Рабочие каталоги

```sh
TRANSLATION_REPO="$HOME/Documents/minecraft-industrial-backrooms"
MODPACK_ROOT="$HOME/Projects/minecraft-industrial-backrooms"
LAUNCHER_ROOT="$HOME/Library/Application Support/sklauncher"
```

Роли каталогов:

- `TRANSLATION_REPO` хранит каталог переводов, манифесты версий, дельты,
  утилиты, исходники переводческого мода и собранные ресурсы;
- `MODPACK_ROOT` хранит точную распакованную целевую версию модпака;
- `LAUNCHER_ROOT` используется для проверки наличия штатной локализации
  Minecraft.

Не полагайся на эти пути вслепую. В начале работы найди каталоги, подтверди
версию модпака и выполни:

```sh
cd "$TRANSLATION_REPO"
git status --short
```

Не отменяй и не включай в свою работу чужие незавершённые изменения.

## Структура данных

### Глобальный каталог

Канонический каталог хранится в репозитории отдельно от результатов сборки:

```text
translation-catalog/catalog.json
```

Логическая структура каталога:

```json
{
  "schema_version": 1,
  "entries": {
    "quest:0123456789abcdef:title": [
      {
        "source_hash": "sha256:7f...",
        "source": "Getting Started",
        "translation": "Начало работы"
      },
      {
        "source_hash": "sha256:31...",
        "source": "A New Beginning",
        "translation": "Новое начало"
      }
    ],
    "quest:0123456789abcdef:description:0": [
      {
        "source_hash": "sha256:a2...",
        "source": "Find a way out.",
        "translation": "Найдите выход."
      }
    ],
    "item:block.refurbished_furniture.plate": [
      {
        "source_hash": "sha256:53...",
        "source": "Plate",
        "translation": "Тарелка"
      }
    ]
  }
}
```

Массив позволяет одному логическому ID иметь несколько английских
формулировок из разных версий модпака. Внутри массива не может быть двух
записей с одинаковым `source_hash`.

`source` хранится обязательно. Хеш нужен для надёжного сопоставления, а
исходная формулировка — для ревью, диагностики и защиты от ошибочного
сопоставления.

Неизменяемость относится к содержимому уже существующих записей. Утилита
добавления может переформатировать JSON, но обязана доказать, что все прежние
объекты сохранились без логических изменений.

Пока каталог полностью неизменяем. Если после публикации обнаружена ошибка,
не редактируй запись самовольно и не создавай вторую запись с той же парой
`ID + source_hash`. Такой случай требует отдельного изменения формата и
политики ревизий.

### Логические ID

Используются следующие ID:

```text
quest:<quest_id>:title
quest:<quest_id>:subtitle
quest:<quest_id>:description:<index>
quest-group:<group_id>:title
quest-chapter:<chapter_id>:title
quest-task:<quest_id>:<task_id>:title
quest-reward:<quest_id>:<reward_id>:title
item:<translation_key>
```

`quest-chapter`, `quest-task` и `quest-reward` используются для видимых
заголовков, которые FTB Quests хранит вне основных текстовых полей квеста.
ID родительского квеста включается в ID задачи или награды, поэтому локальные
ID вложенных объектов не создают коллизий между квестами.

Если извлекатель обнаруживает другой переводимый тип поля, для него сначала
задаётся однозначная схема ID, и только после этого поле допускается в
каталог.

Индекс строки описания считается частью позиции поля в структурно разобранном
SNBT. Пустые строки тоже учитываются при вычислении позиции, даже если сами не
переводятся. Нельзя получать ID регулярным выражением или номером строки
файла.

### Хеш английского оригинала

Хеш вычисляется так:

```python
hashlib.sha256(source.encode("utf-8")).hexdigest()
```

Перед вычислением нельзя:

- обрезать пробелы;
- менять регистр;
- нормализовать Unicode;
- заменять переводы строк;
- удалять коды форматирования;
- изменять подстановки или разметку.

Любое видимое или служебно значимое изменение оригинала должно дать новый
хеш и потребовать проверки перевода.

### Манифест версии

Для каждого выпуска создаётся отдельный воспроизводимый манифест:

```text
translation-versions/<version>/manifest.json
```

Он содержит:

- точную идентификацию модпака, Minecraft, Forge и FTB Quests;
- фактический список установленных модов и их версий;
- путь и SHA-256 каждого исходного файла;
- все извлечённые английские записи;
- их логические ID, типы, расположение и `source_hash`;
- сведения, необходимые для обратной упаковки;
- для предметов — эффективный translation key и namespace;
- отметку о штатном покрытии `ru_ru`, но не сам штатный русский текст.

Манифест является снимком английского оригинала конкретной версии. Он не
содержит переводы и не является частью глобального каталога.

Пример записи:

```json
{
  "id": "quest:0123456789abcdef:description:0",
  "kind": "quest_description",
  "source": "Find a way out.",
  "source_hash": "sha256:a2...",
  "location": {
    "file": "chapters/sector_1.snbt",
    "quest_id": "0123456789abcdef",
    "field": "description",
    "index": 0
  }
}
```

Для предмета:

```json
{
  "id": "item:block.refurbished_furniture.plate",
  "kind": "item_name",
  "source": "Plate",
  "source_hash": "sha256:53...",
  "namespace": "refurbished_furniture",
  "translation_key": "block.refurbished_furniture.plate",
  "native_ru_present": false
}
```

Поле `native_ru_present` можно получить при аудите установленных ресурсов,
но значение штатного русского перевода не импортируется. Оно используется
только для того, чтобы не создавать ненужное переопределение.

### Дельта перевода

Дельта — временный рабочий набор:

```text
translation-versions/<version>/work/pending.tsv
```

В неё попадают только записи, которые:

- присутствуют в манифесте целевой версии;
- требуют собственного перевода;
- не имеют точного совпадения `ID + source_hash` в каталоге.

Для предметов запись со штатным `ru_ru` не требует собственного перевода и в
дельту не попадает. Для квестов перевод требуется всегда, поскольку их
английские строки находятся непосредственно в SNBT.

## Источники истины

Используй источники в следующем порядке:

1. точные английские файлы целевой версии модпака;
2. эффективный `en_us` после всех переопределений, включая KubeJS, когда он
   присутствует;
3. глобальный каталог для точной пары `ID + source_hash`;
4. утверждённый глоссарий;
5. редакторское решение для новой строки.

Штатные `ru_ru` Minecraft и модов не являются источником записей глобального
каталога. Их разрешается проверять только для ответа на вопрос, нужно ли
создавать собственное переопределение translation key. Их текст:

- не копируется в каталог;
- не передаётся агентам как готовый перевод;
- не записывается в `src/resourcepack`;
- не изменяется переводческим модом.

Основные документы:

```text
QUEST_GLOSSARY.md
QUEST_GLOSSARY.tsv
TRANSLATION_METHODOLOGY.md
docs/QUEST_TRANSLATION.md
docs/ITEM_TRANSLATION.md
docs/UPDATING.md
docs/PACKAGING.md
```

При расхождении старых документов с этой методикой правила каталога и сборки
из манифеста имеют приоритет.

## Обычный цикл перевода новой версии

### 1. Подтверждение версии

Зафиксируй:

- название и номер версии модпака;
- CurseForge file ID или другой идентификатор дистрибутива;
- версию Minecraft, Forge и FTB Quests;
- фактический список установленных модов и их версий;
- SHA-256 исходного архива, если он доступен.

Не используй уже переведённые `src/quests` как английский источник.

### 2. Извлечение

Запусти единый извлекатель версии. Он должен:

1. структурно прочитать английские SNBT;
2. получить полный реестр предметов и их эффективные translation keys;
3. разрешить эффективные `en_us`;
4. вычислить логические ID и хеши;
5. проверить только наличие штатного `ru_ru` для предметов;
6. создать детерминированный `manifest.json`.

Извлекатель не должен читать глобальный каталог и не должен создавать
русские файлы. Одинаковый вход обязан давать байт-в-байт одинаковый манифест.

### 3. Вычисление дельты

Сопоставь манифест с каталогом.

Результат должен разделять записи на:

- `CATALOG_HIT` — точная пара `ID + source_hash` уже переведена;
- `NATIVE_RU` — предмет уже покрыт штатной русской локализацией;
- `PENDING` — требуется новый перевод;
- `ERROR` — неоднозначный ID, конфликт хеша, отсутствующий английский текст
  или другая структурная ошибка.

К переводу допускаются только `PENDING`. При наличии `ERROR` работа
останавливается.

Для удобства агенту можно приложить:

- другие формулировки того же ID из каталога;
- переводы такого же `source_hash` под другими ID;
- соседние строки квеста или семейство предметов.

Эти данные являются контекстом, но не считаются автоматическим совпадением.

### 4. Обновление глоссария

До параллельного перевода:

1. просмотри новые и изменившиеся названия;
2. найди повторяющиеся предметы, машины, материалы и измерения;
3. сверь решения с интерфейсом целевой версии;
4. обнови `QUEST_GLOSSARY.md` и `QUEST_GLOSSARY.tsv`;
5. передай компактный TSV каждому переводчику и редактору.

Имена модов и брендов не переводятся: `Create`, `AE2`, `Botania`,
`Mekanism`, `Ender IO`, `JEI`, `KubeJS`, `FTB Quests`.

### 5. Перевод дельты

Разделяй квесты по целым главам, а предметы — по namespace и семействам. Не
дроби связный контекст между агентами.

Базовая инструкция:

```text
Переведи только назначенные записи PENDING с английского на простой,
естественный русский язык для игры.

Правила:
1. Не изменяй id, source_hash, source и количество записей.
2. Заполняй только translation.
3. Сохраняй &- и §-коды, %s, %d, {image:...}, команды, NBT и namespace:id.
4. Используй QUEST_GLOSSARY.tsv.
5. Не переводи бренды, названия модов и технические сокращения.
6. Не добавляй сведений, которых нет в оригинале.
7. Избегай буквальных калек, английского порядка слов и канцелярита.
8. Не редактируй глобальный каталог и файлы других исполнителей.
```

Координатор не добавляет частичный результат в каталог.

### 6. Независимое ревью

Автор не выполняет единственное ревью собственного участка. Первый проход
редакторов проводится без изменения файлов.

Проверяются:

- естественность и понятность русского текста;
- сохранение смысла, условия, действия и предупреждения;
- единообразие терминов и названий семейств;
- соответствие глоссарию и интерфейсным названиям;
- форматирование, подстановки и технические фрагменты;
- точность ID, `source_hash` и числа записей.

Формат замечания:

```text
ID, source_hash, текущий перевод, рекомендуемый перевод, краткая причина
```

Координатор применяет согласованные правки к дельте и запускает повторную
проверку. До добавления в каталог перевод можно исправлять свободно.

### 7. Добавление в каталог

После завершения перевода и ревью используй только специальную операцию
добавления. Она обязана:

1. проверить соответствие каждой записи актуальному манифесту;
2. отклонить изменённые `id`, `source` и `source_hash`;
3. отклонить пустые переводы;
4. отклонить уже существующую пару `ID + source_hash`;
5. проверить неизменность всех прежних записей;
6. добавить только новые утверждённые записи;
7. записать детерминированный каталог;
8. повторным запуском подтвердить отсутствие новых изменений.

Нельзя редактировать `catalog.json` вручную.

### 8. Сборка целевой версии

Сборщик получает:

```text
manifest.json + catalog.json + английские файлы целевой версии
```

Для каждой записи манифеста он:

1. находит точную пару `ID + source_hash`;
2. подставляет утверждённый перевод;
3. пропускает предметы со штатным `ru_ru`;
4. выдаёт ошибку, если обязательный перевод отсутствует.

Сборщик не имеет права перебирать каталог и выгружать все известные записи.
Направление обхода всегда такое:

```text
манифест целевой версии -> точный поиск в каталоге -> выходной ресурс
```

Результат:

```text
src/quests/
src/resourcepack/assets/<namespace>/lang/ru_ru.json
```

В `src/quests` попадает полный структурный набор квестов целевой версии с
переведёнными видимыми полями.

В собственные `ru_ru.json` попадают только translation keys, которым нужен
перевод проекта в этой версии. Штатные русские строки Minecraft и модов не
копируются и не переопределяются.

Удалённые из целевой версии квесты и предметы исчезают из собранных ресурсов,
но навсегда остаются в глобальном каталоге.

## Правила перевода

### Тон

- Пиши так, как обычно пишут в игровом интерфейсе.
- Используй короткие предложения и знакомые слова.
- Отдавай предпочтение действию: `Положите`, `Соедините`, `Найдите`.
- Не имитируй английский порядок слов.
- Не усложняй фразу ради технической точности, которая игроку не нужна.
- Сохраняй атмосферный тон художественного текста.
- Не переноси английскую капитализацию каждого слова в русский текст.

### Терминология

- Одному объекту в рамках версии соответствует одно русское UI-имя.
- Сначала определяется название предмета, затем оно используется в квестах.
- Используй официальные термины Minecraft: `редстоун`, `скалк`, `Незер`,
  `Энд`, `эндерняк`, `тихоня`, `лавомерка`.
- Сохраняй принятые сокращения: `ME`, `P2P`, `FE`, `RF`, `NBT`.
- `Backrooms` и `Poolrooms` являются собственными именами.
- Намеренно оставлены `Ars Ecclesia`, `"Enderios"`, `Snad` и `Suol Snad`.

### Что нельзя менять

- ID квестов, предметов и translation keys;
- структуру SNBT, зависимости, задачи и награды;
- `namespace:path`, команды, NBT, координаты и имена файлов;
- коды форматирования `&o`, `&l`, `&6`, `§6`;
- подстановки `%s`, `%d` и разметку `{image:...}`;
- английский оригинал и его `source_hash`.

## Проверки

### Проверка каталога

- JSON соответствует схеме;
- каждый хеш совпадает с сохранённым `source`;
- нет дубликатов `ID + source_hash`;
- все значения `source` и `translation` непустые;
- старые записи не изменены и не удалены;
- повторное добавление той же дельты ничего не меняет.

### Проверка покрытия версии

Для каждой записи манифеста должен существовать ровно один допустимый исход:

```text
точный перевод из каталога
или
штатное ru_ru для предмета
```

Ни одна запись другой версии не должна попасть в результат.

Отчёт сборки обязан показывать:

```text
всего английских записей
совпадений с каталогом
штатно покрытых предметов
новых переводов
отсутствующих переводов
выходных квестовых строк
выходных item translation keys
```

Готовность требует `PENDING = 0`, `ERROR = 0` и отсутствия неиспользованных
ключей в собранном ресурс-паке.

### Структурная проверка квестов

- набор файлов, квестов и групп совпадает с английским оригиналом версии;
- изменены только переводимые поля;
- сохранено число элементов описаний, включая пустые;
- сохранены ID, зависимости, задачи, награды и форматирование;
- исходные SHA-256 соответствуют манифесту.

### Проверка предметов

- полнота реестра подтверждена для целевой версии;
- ProbeJS используется, когда он доступен и содержит полный реестр; в
  остальных случаях используется другой воспроизводимый источник;
- проверяются не только `item.*`, но также `block.*`, `fluid.*`,
  `fluid_type.*` и `entity.*`;
- собственный ресурс-пак не содержит ключей со штатным `ru_ru`;
- все JSON корректны;
- один translation key имеет не более одного выходного значения;
- названия предметов совпадают с формулировками квестов и глоссарием.

### Тесты и сборка

```sh
cd "$TRANSLATION_REPO/mod"
./gradlew clean test build
```

Тесты должны дополнительно проверять, что встроенные ресурсы получены из
одного манифеста версии и не содержат записей каталога, отсутствующих в этом
манифесте.

## Ручная проверка в игре

Установи собранный JAR в чистый профиль точной версии и проверь:

1. при `ru_ru` переведены названия глав, квестов и описания;
2. при другом языке отображается оригинальный текст;
3. смена языка не изменяет файлы квестов;
4. перевод работает на сервере без переводческого мода;
5. новые собственные названия предметов отображаются в JEI;
6. штатные русские названия Minecraft и модов сохранились;
7. награды и требования используют те же названия, что JEI;
8. длинные названия и описания помещаются в интерфейсе;
9. форматирование, изображения и подстановки не сломаны;
10. в журнале нет сообщения о несовместимом наборе ID.

## Частые ошибки

- Выгружать в мод весь глобальный каталог вместо записей целевой версии.
- Считать совпадение только по ID и не проверять хеш оригинала.
- Автоматически переносить перевод одинакового текста между разными ID.
- Нормализовать английский текст перед хешированием.
- Редактировать или удалять старую запись каталога.
- Добавлять в каталог перевод до завершения независимого ревью.
- Импортировать штатные `ru_ru` Minecraft или модов в каталог.
- Копировать штатные русские строки в собственный ресурс-пак.
- Извлекать английский текст из уже переведённых SNBT.
- Переводить только предметы, упомянутые в квестах.
- Искать только ключи `item.*`.
- Слепо переводить ID с подчёркиваниями как отображаемое имя.
- Запаковывать частичную дельту.
- Сохранять удалённые строки старой версии в новом JAR.
- Включать в коммит чужие незавершённые изменения.

## Итоговый чек-лист координатора

- [ ] Точная версия модпака подтверждена.
- [ ] Английский оригинал извлечён в отдельный манифест.
- [ ] Манифест воспроизводим и содержит хеши исходных файлов.
- [ ] Полный реестр предметов получен из ProbeJS или другого
      воспроизводимого источника и проверен на полноту.
- [ ] Выполнено точное сопоставление `ID + source_hash` с каталогом.
- [ ] Штатные `ru_ru` только учтены как покрытие и не импортированы.
- [ ] Агентам переданы только записи `PENDING`.
- [ ] Глоссарий обновлён до начала параллельного перевода.
- [ ] Другие агенты выполнили независимое ревью.
- [ ] Все замечания разрешены до добавления записей в каталог.
- [ ] В каталог только добавлены новые записи.
- [ ] Проверена неизменность всей старой части каталога.
- [ ] Повторный запуск добавления идемпотентен.
- [ ] `PENDING = 0` и `ERROR = 0`.
- [ ] Ресурсы собраны обходом манифеста целевой версии.
- [ ] В результате нет строк из других версий.
- [ ] В собственном ресурс-паке нет штатно переведённых ключей.
- [ ] Квесты, глоссарий и UI используют одинаковые названия.
- [ ] `./gradlew clean test build` проходит.

Выполни цикл:
