# Перевод квестов Liminal Industries

Полная актуальная методика находится в `TRANSLATION_METHODOLOGY.md`. Этот
документ служит краткой памяткой по квестам.

## Где хранятся квесты

Серверные файлы FTB Quests находятся на диске хоста:

```text
data/config/ftbquests/quests/
```

Каталог `./data` подключён в контейнер как `/data`, поэтому для изменения
квестов не требуется пересобирать Docker-образ или контейнер. На внешнем
сервере клиент получает структуру и тексты квестов с сервера.

Модпак закреплён на конкретном CurseForge-файле `8509377`. Автоматического
перехода на новые версии нет. В `compose.yaml` также установлены:

```yaml
CF_FORCE_SYNCHRONIZE: "FALSE"
CF_OVERRIDES_SKIP_EXISTING: "TRUE"
```

Это предотвращает повторное применение файлов модпака поверх существующего
перевода при обычном запуске. Перед намеренным обновлением модпака необходимо
сделать отдельную резервную копию каталога квестов.

## Инструменты

Используются два скрипта:

```text
scripts/extract_quest_texts.py
scripts/pack_quest_texts.py
```

Стратегия терминологии и проверенный глоссарий находятся в:

```text
QUEST_GLOSSARY.md
QUEST_GLOSSARY.tsv
```

Markdown-документ объясняет источники, коллизии и правила. Компактный TSV
предназначен для непосредственной передачи переводящим агентам.

Скрипт извлечения создаёт каталог `translation-work/`. Переводимые файлы
повторяют структуру исходных глав и имеют формат:

```text
1	You can use brushes to sweep up the carpet for carpet dust.
2	&oNote: The effects of long term carpet dust exposure are unknown.
```

Каждая запись содержит короткий ID, символ табуляции и текст. Переводить нужно
только часть после первой табуляции.

Файл `translation-work/_map.json` является служебным. Его не нужно отправлять
модели, переводить или редактировать. Он хранит соответствие строк исходным
SNBT-файлам и их контрольные суммы.

Пустые строки внутри описаний не извлекаются: они используются как разделители
абзацев и автоматически остаются в исходных файлах.

## Цикл работы

Рабочие файлы и скрипты находятся в репозитории перевода, а исходные SNBT
берутся из отдельного каталога модпака:

```sh
TRANSLATION_REPO="$HOME/Documents/minecraft-industrial-backrooms"
MODPACK_ROOT="$HOME/Projects/minecraft-industrial-backrooms"
cd "$TRANSLATION_REPO"
```

### 1. Извлечение

```sh
python3 scripts/extract_quest_texts.py \
  --source "$MODPACK_ROOT/data/config/ftbquests/quests" \
  --output translation-work
```

Если `translation-work/` уже содержит предыдущий цикл и его действительно
можно удалить:

```sh
python3 scripts/extract_quest_texts.py \
  --source "$MODPACK_ROOT/data/config/ftbquests/quests" \
  --output translation-work \
  --force
```

Параметр `--force` нельзя использовать, пока незавершённый перевод не сохранён:
он заменяет содержимое рабочего каталога.

Текущее состояние сборки содержит 841 непустую переводимую строку, примерно
6559 английских слов.

### 2. Перевод

Редактируются только `.txt`-файлы внутри `translation-work/`. Нельзя:

- менять ID перед табуляцией;
- удалять или добавлять записи;
- объединять две записи в одну;
- добавлять переносы строки внутрь записи;
- изменять `_map.json`;
- удалять коды форматирования вроде `&o`, `&l` или `&6`.

Названия модов, машин, предметов и измерений следует переводить строго по
`QUEST_GLOSSARY.tsv`. Если термин помечен фактически одинаковой английской
строкой в обеих колонках, это `KEEP_EN`: переводить или склонять его нельзя.

### 3. Проверка

```sh
python3 scripts/pack_quest_texts.py \
  --input translation-work \
  --source "$MODPACK_ROOT/data/config/ftbquests/quests" \
  --check
```

Команда проверяет:

- наличие всех ID;
- отсутствие неизвестных и повторяющихся ID;
- количество записей;
- наличие всех исходных файлов;
- соответствие исходников состоянию на момент извлечения.

В режиме `--check` серверные файлы не изменяются.

### 4. Запаковка

```sh
python3 scripts/pack_quest_texts.py \
  --input translation-work \
  --source "$MODPACK_ROOT/data/config/ftbquests/quests"
```

Перед записью упаковщик создаёт резервную копию изменяемых SNBT-файлов:

```text
translation-work/backups/YYYYMMDD-HHMMSS/
```

После успешной запаковки перед следующим циклом требуется заново выполнить
извлечение. Старый `_map.json` больше не соответствует изменённым SNBT-файлам.

### 5. Запуск сервера

Сервер желательно останавливать перед запаковкой. После завершения перевода:

```sh
(cd "$MODPACK_ROOT" && docker compose up -d)
(cd "$MODPACK_ROOT" && docker compose logs -f minecraft)
```

Клиенты получат обновлённые тексты при подключении к серверу.

## Параллельный перевод

Оптимальная схема для доступных четырёх рабочих слотов: три переводящих
сабагента и один основной агент-координатор. Файлы не следует дробить внутри,
чтобы агенты не конфликтовали и сохраняли контекст главы.

Рекомендуемое распределение:

| Исполнитель | Файлы | Примерный объём |
| --- | --- | ---: |
| Сабагент 1 | `sector_2.txt`, `chapter_3b.txt` | 2380 слов |
| Сабагент 2 | `sector_1.txt`, `sector_3.txt` | 2175 слов |
| Сабагент 3 | `sector_21.txt`, `sector_4.txt`, `the_infinite_library.txt`, `escaping.txt`, `chapter_groups.txt` | 2004 слова |
| Координатор | Глоссарий, проверка, объединение и запаковка | — |

Все сабагенты работают только со своими файлами в общем каталоге
`translation-work/`. Упаковщик запускается координатором один раз после
завершения всех трёх частей.

## Общая инструкция сабагентам

```text
Переведи назначенные файлы с английского на естественный русский язык.

Правила:
1. Переводи только текст после первой табуляции.
2. Не изменяй ID, табуляцию и количество строк.
3. Не добавляй переносы строк.
4. Сохраняй коды форматирования вроде &o, &l и &6.
5. Используй QUEST_GLOSSARY.tsv для предметов, измерений и механизмов.
6. Не переводи технические идентификаторы и названия модов.
7. Сохраняй смысл, тон и подсказки по игровым механикам.
8. Не редактируй никакие файлы за пределами назначенного списка.
```

## Глоссарий и контроль качества

До запуска сабагентов нужно согласовать небольшой общий глоссарий для
повторяющихся терминов: названия измерений, материалов, машин, механик Create,
Immersive Engineering, Botania и Applied Energistics 2.

После параллельного перевода рекомендуется отдельный контрольный проход:

1. Проверить единообразие терминов и обращения к игроку.
2. Найти случайно оставшиеся английские предложения.
3. Проверить сохранность кодов форматирования.
4. Запустить `pack_quest_texts.py --check`.
5. Запаковать перевод и просмотреть несколько длинных квестов в игре.

Упаковщик защищает структуру файлов, но не оценивает качество или смысл
перевода, поэтому терминологический контроль остаётся отдельным этапом.
