# Источники переводимых текстов

Набор источников каждой версии задаётся в
`translation-versions/<version>/sources.json`. Оркестратор
`build_version_delta.py` загружает конфигурацию и вызывает зарегистрированный
адаптер для каждого источника. Порядок и состав источников больше не зашиты в
основной цикл построения манифеста.

## Контракт адаптера

Адаптер возвращает:

- `records` — стабильные логические записи с исходным текстом, хэшем,
  местоположением и форматом результата;
- `source_files` — все файлы и члены архивов, от которых зависит извлечение;
- `report` — счётчики, специфичные для источника.

Оркестратор добавляет к каждой записи `source_id` и `source_type`, проверяет
уникальность ID и объединяет отчёты. Общие форматы результата:

- `lang` — ключ в `assets/<namespace>/lang/ru_ru.json`;
- `patchouli_json` — поле локализованного JSON Patchouli;
- FTB Quests — структурная замена поля в SNBT.

## Включённые источники

- `ftb_quests` — заголовки и описания FTB Quests;
- `registry_items` — реальные предметы реестра;
- `registry_blocks` — самостоятельный реестр блоков;
- `patchouli` — метаданные, категории, статьи и страницы Patchouli.

Блоки не выводятся из списка предметов. Для Rescripted используется тип
ProbeJS `Block`; для Original предусмотрен fallback по всем blockstate-моделям
и блокам из startup-скриптов KubeJS. Наличие английского lang-ключа не является
условием сбора: его отсутствие само по себе должно быть заметно в дельте.

## Patchouli

Адаптер просматривает:

```text
data/<namespace>/patchouli_books/<book>/book.json
assets/<namespace>/patchouli_books/<book>/en_us/**/*.json
```

Поля `name`, `title`, `subtitle`, `description`, `landing_text`, `text` и
`link_text` считаются видимыми. Если значение является ключом из `en_us`, оно
попадает в обычный `ru_ru.json`. Литеральный текст записывается в зеркальный
JSON под каталогом `ru_ru`. Ссылки, рецепты, иконки, типы страниц и прочая
структура копируются без изменений.

Значения шаблонов Patchouli, начинающиеся с `#`, не считаются текстом.
Разметка Patchouli остаётся частью исходной строки и проверяется при
утверждении перевода.

## Добавление источника

1. Реализовать collector, возвращающий `SourceResult`.
2. Зарегистрировать имя адаптера в `build_version_delta.py`.
3. Если появляется новый формат результата, добавить builder в
   `build_version_resources.py`.
4. Добавить источник в `sources.json` нужных версий.
5. Для runtime-проверяемого источника добавить `AuditProvider` с таким же ID.
6. Назначить новые namespace выходным resource pack в `resource-packs.json`.
7. Добавить fixture-тест извлечения и построения ресурсов.

Audit-мод получает `sources.json` выбранной версии при сборке. Источник с
`"audit": false` намеренно не требует runtime-провайдера. Для остальных
отсутствующий провайдер или нулевой результат считается ошибкой аудита.

## Незавершённые переводы

Новый источник может сразу создать pending-записи. Существующие переводы из
payload используются как подсказки в `work/pending.tsv`. Проверенную часть
можно переносить в каталог независимо:

```sh
python3 scripts/approve_version_translations.py \
  --version <version> \
  --allow-partial
```

Payload остаётся последней завершённой сборкой, пока в манифесте есть pending.

При утверждении `block_name` скрипт сопоставляет `block_id` с `item_id` в том
же манифесте. Если для item-записи текущего исходного текста уже есть перевод
в неизменяемом каталоге (или он утверждается в том же пакете), перевод блока
обязан совпадать с ним буквально.
