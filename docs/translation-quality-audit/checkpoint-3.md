# Чекпоинт 3: редакционное утверждение

Дата проверки: 2026-08-05.

Обычное утверждение по-прежнему только добавляет новую точную пару
`ID + source_hash`. Конфликт с уже утверждённым текстом завершается ошибкой.

Для исправления существующей пары добавлена отдельная операция:

```sh
python3 scripts/approve_version_translations.py \
  --version <version> \
  --corrections /path/to/corrections.tsv
```

TSV обязан содержать `id`, `source_hash`, `old_translation`,
`new_translation`, `reason` и `independent_review`. Операция принимает только
точное значение `APPROVED`, проверяет старый текст, manifest, разметку и
технические токены, затем сохраняет полную запись в `catalog.corrections`.

`catalog.entries_hash` блокирует прямое изменение реестра в обход операции
утверждения. `validate_catalog` также проверяет последовательность всех
коррекций и совпадение последней редакции с текущим текстом.

Manifest теперь сохраняет фактический штатный русский текст. Для lang-записей
сборщик не добавляет утверждённый текст в payload, если он точно совпадает со
штатным, и создаёт override, если утверждённая редакция отличается.

Проверки доказывают:

- добавление новой утверждённой пары;
- исправление существующей пары с сохранением редакционных данных;
- отказ без независимого `APPROVED`;
- отказ после тихого ручного изменения catalog;
- отсутствие лишнего payload для совпадающего штатного текста и создание
  override для исправленного штатного текста.
