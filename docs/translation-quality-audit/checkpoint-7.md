# Чекпоинт 7: защита будущих обновлений

Дата проверки: 2026-08-05.

Каждая запись обоих манифестов теперь содержит фактические
`effective_translation`, `effective_translation_origin` и
`effective_translation_approved`. Признак утверждения выставляется только
командой экспорта с полным `quality-review.tsv`; простой повторный экспорт
сохраняет его лишь при неизменных тексте и происхождении.

Построитель новой дельты индексирует утверждённые записи сохранённых
версионных манифестов. Штатный текст или версионный override получает
`FINALIZED` только при точном совпадении `ID`, `source_hash`, английского
текста, типа, source, location-контекста и доступной русской формулировки.
Точная каталожная пара по-прежнему переиспользуется автоматически. Новый ID,
новый хеш, изменившийся эффективный override или ещё не утверждённый штатный
текст получает `REVIEW_NATIVE`/`PENDING`.

Сборщик payload теперь явно блокирует все незакрытые статусы, даже если в
каталоге существует старый вариант того же ID. Payload по-прежнему полностью
пересоздаётся из текущего манифеста, поэтому удалённые записи не сохраняются.

## Проверки

- Реальное повторное построение Original: 19 853 записи, 7 232 точных
  catalog hits, 0 строк дельты.
- Реальное повторное построение Rescripted: 22 659 записей, 9 618 точных
  catalog hits, 0 строк дельты.
- Во всех 42 512 записях сохранены эффективный текст, происхождение и
  `effective_translation_approved=true`.
- Unit-тест обновления подтверждает сохранение точной утверждённой записи,
  исключение удалённого ID и появление нового ID и изменённого `source_hash`
  со статусом `REVIEW_NATIVE`.
- Отдельный тест подтверждает отказ сборки при неутверждённом штатном тексте.
- `PYTHONPATH=scripts python3 -m unittest discover -s scripts/tests`: 66
  тестов, `OK`.
- Оба payload проходят `build_version_resources.py --check`, обе эффективные
  выгрузки проходят `export_effective_translations.py --check` с полным
  review ledger.

Контракт обновления описан в `TRANSLATION_METHODOLOGY.md` и
`docs/UPDATING.md`.
