# Runtime-аудит переводимых текстов

`audit-mod` — отдельный служебный Forge-мод. Его классы и зависимость от JEI
не входят в публикуемый JAR перевода.

## Сборка

```sh
./mod/gradlew -p audit-mod clean test build \
  -PtranslationVersion=1.19.3-original

./mod/gradlew -p audit-mod clean test build \
  -PtranslationVersion=1.19.3-7-ae2-fix
```

Gradle выбирает версию обязательного translation-мода из общего
`translation-versions/<version>/build-config.json`. Результат:

```text
audit-mod/build/libs/liminal-industries-russian-translation-audit-<version>.jar
```

## Проверка в игре

1. Установить релизный JAR перевода и JAR аудита в реальный клиентский профиль
   соответствующего модпака.
2. Запустить игру, выбрать `Русский (Россия)` и войти в мир.
3. Дождаться полной загрузки JEI.
4. Выполнить клиентскую команду `/liminal_ru_audit`.
5. Проверить итог `PASS` и отчёт:

```text
liminal-industries-ru-audit/item-name-audit.json
```

Имя файла отчёта сохранено для совместимости с прежним item-only аудитом.

Команда `/liminal_ru_books` выдаёт игроку по одному экземпляру каждой книги,
содержимое которой входит в выбранную версию перевода. Команда работает на
встроенном сервере одиночного мира, чтобы изменение инвентаря было
сервер-авторитетным. Для версии `1.19.3-7-ae2-fix` она выдаёт 13 книг:
6 книг Patchouli, 6 книг Tinkers' Construct и руководство Immersive
Engineering. Если инвентарь заполнен, оставшиеся книги появляются рядом с
игроком.

Список книг создаётся из `translation-audit-index.json`. Каждый провайдер
источника переопределяет способ преобразования ID книги в `ItemStack`;
провайдеры, не связанные с книгами, используют пустую реализацию по умолчанию.

Состав аудита берётся из `translation-versions/<version>/sources.json`.
Провайдерная архитектура связывает ID источника со способом runtime-проверки.
Отсутствующий провайдер и неожиданно пустой результат завершают аудит ошибкой.

Аудит объединяет все варианты `ItemStack`, фактически зарегистрированные в
JEI, с базовыми стеками всего runtime-реестра предметов Minecraft. Отдельно он
обходит весь runtime-реестр блоков, чтобы проверять `block.*` даже тогда, когда
соответствующий предмет использует независимый и уже переведённый `item.*`.
Провайдер Patchouli проверяет локализованные JSON-ресурсы и language keys,
включая метаданные из сгенерированного `translation-audit-index.json`.
Провайдер Immersive Engineering проверяет статьи текстового руководства,
число строк и управляющие маркеры. Провайдер Mantle строго разбирает книги
Tinkers' Construct и проверяет все видимые поля, включённые в манифест.

Для отображаемого компонента имени проверяются только translation keys, которые
действительно использует выбранный русский шаблон. Неиспользуемые аргументы
компонента не влияют на результат. Ключ считается русским, если он присутствует
в реально загруженном `ru_ru.json` либо его runtime-значение отличается от
английского: это учитывает переводы, которые моды создают программно или
передают как fallback самого компонента. Нейтральные шаблоны вроде `%1$s-%2$s`
не требуют отдельного русского ключа. Английский fallback с обычным текстом
по-прежнему не засчитывается.

Литеральное поле книги считается локализованным, если соответствующая строка
или JSON pointer присутствует в реально загруженном `ru_ru`-ресурсе.
Невалидный JSON, устаревшая структура TXT и пропущенные поля завершают аудит
ошибкой. Это позволяет намеренно оставлять без изменения имена авторов,
названия модов, ссылки и нейтральные знаки, прошедшие сбор и ревью.

`FAIL` вызывают:

- отсутствующий русский translation key;
- пустое имя или исключение при его получении;
- буквальное имя без translation key и без кириллицы, которое нельзя
  автоматически подтвердить как русское.

Совпадения русского и английского значений записываются в
`same_as_english_keys` для редакторской проверки, но сами по себе не вызывают
`FAIL`: названия модов, аббревиатуры и имена собственные могут совпадать
намеренно.

## Аудит верстки книг

Клиентская команда:

```text
/liminal_ru_layout_audit
```

проходит реальные landing-, category- и entry-экраны Patchouli сначала в
`en_us`, затем в `ru_ru`. Для каждой страницы аудит ждёт три кадра, читает
bounding box уже разложенных `BookTextRenderer` слов с учетом масштаба GUI и
проверяет выход за страницу, clipping, пересечение с элементами управления и
наложение строк. Заблокированные записи создаются напрямую из runtime-модели
книги, поэтому прогресс игрока не меняется.

Отчет и необязательный HTML-индекс сохраняются в:

```text
liminal-industries-ru-audit/book-layout-audit.json
liminal-industries-ru-audit/book-layout-audit.html
```

Снимки создаются только для проблемных экранов в каталоге `screenshots`.
Дефекты, воспроизводимые в обоих языках, получают классификацию
`UPSTREAM_LAYOUT`; только русские дефекты — `TRANSLATION_LAYOUT`. Сборку
блокируют только русские `ERROR`.

Сгенерированный `translation-audit-index.json` имеет schema 3 и содержит
`book_screens` с движком, книгой, ресурсом, entry/page и источником текста.
Индекс включает Patchouli, Mantle/Tinkers' Construct и руководство Immersive
Engineering. Runtime-адаптер Patchouli дополнительно перечисляет фактически
загруженные страницы, включая нативные строки вне каталога переводов.

Для автоматического smoke-прохода подготовьте локальный мир
`audit-mod/run-layout-audit/saves/Liminal Layout Audit` и каталог `mods` с
модами проверяемой сборки и JAR перевода, затем выполните:

```sh
./mod/gradlew -p audit-mod runLayoutAuditClient \
  -PtranslationVersion=1.19.3-7-ae2-fix
```

Задача сама входит в мир, запускает аудит, завершает клиент и возвращает
ошибку Gradle, если отчет отсутствует или содержит `TRANSLATION_LAYOUT ERROR`.
