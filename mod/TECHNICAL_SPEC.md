# Техническая спецификация

## Назначение

Мод добавляет русский перевод названий предметов и текста FTB Quests для
поддерживаемых версий Liminal Industries и Liminal Industries - Rescripted.

Целевое окружение:

- Minecraft `1.20.1`;
- Forge `47.4.13`;
- FTB Quests `2001.4.13` или `2001.4.22`, в зависимости от артефакта;
- Java `17`.

Это клиентский мод. Он работает в одиночной игре и при подключении к серверу,
на котором мод не установлен.

## Архитектура

Языковые файлы из `translation-versions/<version>/payload/resourcepack`
включаются в JAR как обычные ресурсы Forge. Переведённые SNBT-файлы из
`payload/quests` включаются как неизменяемые ресурсы. Gradle создаёт для них индекс
`liminal_industries_ru/quest-files.list`.

JAR регистрирует свой обязательный клиентский пак в позиции `BOTTOM`. Поэтому
он автоматически активен и перекрывает ресурсы модов, но обычные пользовательские
ресурс-паки располагаются выше и могут заменить любой его текст.

Для Patchouli, Immersive Engineering Manual и Mantle/TConstruct Gradle создаёт
детерминированный `book-translations.json`: адрес исходного и русского ресурса,
SHA-256 исходного ресурса и пары `адрес поля + исходник + перевод`. При загрузке:

1. точный SHA-256 возвращает готовый русский ресурс байт-в-байт;
2. для обновлённого JSON сначала проверяется исходный JSON pointer, затем
   допускается только единственное совпадение `исходник + имя поля`;
3. для IE сначала проверяется номер строки, затем единственное совпадение всей
   исходной строки;
4. для `language.lang` проверяются стабильный ключ и его исходное значение.

Новые поля остаются на языке upstream. Изменённые и неоднозначные поля не
получают старый перевод. Отсутствующий или невалидный исходный ресурс скрывает
наш устаревший русский файл целиком. Результаты `EXACT`, `ADAPTED`,
`SOURCE_CHANGED`, `MISSING_SOURCE` и `INVALID_SOURCE` доступны runtime-аудиту.

Версионные исправления исходных книг находятся в
`compatibility-resourcepack`. Они не включаются в JAR и собираются отдельным
необязательным ZIP, который пользователь может включить, отключить или
переопределить независимо от перевода.

Те же языковые файлы на этапе сборки распределяются по независимым
ресурс-пакам согласно `resource-packs.json`. Скрипт проверяет точную партицию
ключей и воспроизводимость ZIP. Ресурс-паки не содержат SNBT квестов:
classpath-загрузка и проверка ID доступны только в JAR.

При первом запросе текста квеста клиент:

1. читает индекс и SNBT только из classpath JAR;
2. загружает для каждого `title`, `subtitle` и элемента `description`
   исходный текст из манифеста целевой версии;
3. находит поле по ID объекта и позиции поля;
4. подставляет русский текст только при точном совпадении текущего исходника и
   выбранном языке `ru_ru`.

Mixin-инъекции перехватывают возвращаемые значения:

- `QuestObjectBase#getTitle`;
- `Quest#getSubtitle`;
- `Quest#getDescription`.

Оригинальные объекты FTB Quests и их сериализованные данные не изменяются.
Добавленные и удалённые объекты не влияют на остальные переводы. Изменённое
поле или повторно использованный ID остаются нетронутыми; несовпадение одной
строки `description` не отключает совпавшие строки того же описания.

## Работа с файлами

Производственный код не читает и не записывает каталог игры. В частности, мод:

- не заменяет файлы FTB Quests;
- не создаёт резервные копии;
- не устанавливает resource pack;
- не хранит состояние между запусками.

Поэтому удаление JAR полностью отключает перевод и сразу возвращает оригинальное
отображение.

## Совместимость

Зависимость от FTB Quests обязательна только на клиенте. Её диапазон берётся из
`build-config.json` выбранной версии. Точная пара `ID + поле + исходный текст`
защищает от применения текста к другому объекту, но допускает независимые
добавления, удаления и изменения квестов.

Source-aware адаптер книг читает effective `en_us` из выбранного стека
resource pack в его реальном порядке приоритета, исключая собственный baseline.
Прямое чтение установленных mod JAR используется только как консервативный
fallback, если effective-ресурс недоступен. Поэтому пользовательский `en_us`
участвует в проверке исходника, а полное пользовательское переопределение
`ru_ru` всегда имеет приоритет.

## Сборка и тесты

Команда:

```sh
cd mod
./gradlew clean test build -PtranslationVersion=<version>
```

Тесты проверяют:

- корректность и отсутствие дубликатов в `ru_ru.json`;
- отсутствие `en_us` и технических исправлений в основном payload;
- отсутствие ссылок книг на автоматически сгенерированные `*:kjs/<hash>` ID;
- полное и однократное распределение языковых ключей по ресурс-пакам;
- отсутствие неизвестных ключей и воспроизводимость ZIP;
- чтение всех встроенных SNBT-файлов;
- ожидаемый набор ID и контрольные фрагменты перевода;
- независимое поведение добавленных, удалённых и изменённых полей книги.
- точный book-resource байт-в-байт и консервативное объединение при вставке,
  изменении, удалении и неоднозначном повторе текста.

Готовый JAR создаётся в `mod/build/libs`, ZIP-паки — в
`mod/build/resourcepacks/<version>`, а необязательный compatibility ZIP — в
`mod/build/compatibilitypacks/<version>`. Задача `assembleTranslationRelease`
собирает все виды артефактов в `mod/build/releases/<version>`.
