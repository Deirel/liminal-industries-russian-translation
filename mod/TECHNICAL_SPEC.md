# Техническое задание

## 1. Цель

Собрать один Forge-мод, который устанавливается в существующий профиль
Liminal Industries - Rescripted через CurseForge и добавляет:

1. русский перевод названий из языковых JSON-файлов;
2. русский перевод книги FTB Quests в одиночной игре;
3. тот же перевод на выделенном сервере, если JAR установлен на сервер.

Первая версия решает только эту задачу. В ней нет GUI, собственного формата
конфигурации, обновления через сеть, редактора перевода и интеграции с KubeJS.

## 2. Целевая среда

| Компонент | Проверенная версия |
| --- | --- |
| Minecraft | 1.20.1 |
| Forge | 47.4.13 |
| Java | 17 |
| Liminal Industries - Rescripted | 1.19.3 - 7 (AE2 fix) |
| FTB Quests | 2001.4.22 |

Forge `47.4.13` является минимальной поддерживаемой версией. Файл мода
объявляет совместимость только с Minecraft `1.20.1`, Forge `47.4.13` или новее
в ветке Forge 47 и FTB Quests `2001.4.22`.

Совместимость с конкретной книгой Liminal Industries определяется не по имени
модпака, а по полному набору путей и SHA-256 исходных квестовых файлов.

## 3. Почему нужны два механизма

Forge автоматически включает ресурсы модов в набор `Mod Resources` и объединяет
языковые JSON-файлы по ключам. Поэтому Gradle подключает
`../src/resourcepack/assets/<namespace>/lang/ru_ru.json` как ресурсы мода. Код
для загрузки этих файлов не нужен.

FTB Quests для Minecraft 1.20.1 хранит текст книги непосредственно в
`config/ftbquests/quests/*.snbt`. Эта версия не предоставляет современный
механизм отдельного файла локализации книги. Поэтому переведённые SNBT необходимо
однократно установить в каталог конфигурации до запуска сервера.

## 4. Структура проекта

Мод находится в подпапке основного репозитория перевода:

```text
src/
├── resourcepack/
│   ├── pack.mcmeta
│   └── assets/<namespace>/lang/ru_ru.json
└── quests/
    ├── data.snbt
    ├── chapter_groups.snbt
    └── chapters/*.snbt
mod/
├── gradle/
├── src/
│   ├── main/
│   │   ├── java/ru/deirel/liminalindustries/translation/
│   │   ├── payload/payload-manifest-template.json
│   │   └── resources/META-INF/mods.toml
│   └── test/java/
├── build.gradle
├── gradle.properties
├── gradlew
├── gradlew.bat
└── settings.gradle
```

Рабочие идентификаторы:

```text
display name: Liminal Industries: Russian Translation
mod id:       liminal_industries_ru
package:      ru.deirel.liminalindustries.translation
```

Перед созданием Gradle-проекта необходимо определить автора и лицензию:
поле `license` в `mods.toml` обязательно.

## 5. Исходники перевода

Канонический перевод находится в корне этого репозитория:

```text
src/resourcepack/assets/
src/quests/
```

Gradle подключает эти каталоги как ресурсы мода по относительному пути и
генерирует карту `translatedFiles` в manifest при сборке. Копировать перевод в
`mod/src/main/resources` нельзя: один и тот же commit должен содержать ровно
один актуальный набор переводов и собираться локально или в CI без доступа к
соседнему проекту.

`originalFiles` формируется отдельно из чистого профиля CurseForge с
[файлом модпака 8509377](https://www.curseforge.com/minecraft/modpacks/liminal-industries-rescripted/files/8509377).
Нельзя вычислять контрольные суммы оригинала по переведённому снимку.

Языковые файлы сохраняют исходные пространства имён:

```text
assets/ae2/lang/ru_ru.json
assets/create/lang/ru_ru.json
assets/kubejs/lang/ru_ru.json
...
```

Перевод SNBT должен менять только отображаемый текст. Идентификаторы глав,
квестов, задач и наград должны совпадать с оригиналом, иначе существующий
прогресс может стать недоступен.

## 6. Метаданные Forge

Использовать `javafml`, ForgeGradle 6 и Java toolchain 17. Главный класс
помечается `@Mod("liminal_industries_ru")`. Регистрация блоков, предметов,
capabilities, mixin и сетевого канала не требуется.

Минимальные значения `mods.toml`:

| Поле | Значение |
| --- | --- |
| `loaderVersion` | `"[47,)"` |
| `features.java_version` | `"[17,18)"` |
| `minecraft.versionRange` | `"[1.20.1]"` |
| `forge.versionRange` | `"[47.4.13,48)"` |
| `ftbquests.versionRange` | `"[2001.4.22]"` |
| `ftbquests.ordering` | `"BEFORE"` |
| `side` для всех зависимостей | `"BOTH"` |

Зависимость FTB Quests обязательна и действует на обеих физических сторонах.
`ordering = "BEFORE"` гарантирует запуск установщика до инициализации FTB
Quests.
`showAsResourcePack` остаётся `false`: языковые файлы должны входить в общий
`Mod Resources`.

Наличие этого мода на другой стороне соединения не обязательно. В
`mods.toml` используется `displayTest = "NONE"`, а в главном классе
регистрируется стандартный для Forge `IExtensionPoint.DisplayTest`, принимающий
отсутствие мода на удалённой стороне. Это влияет только на проверку совместимости
при подключении и не отключает загрузку JAR на клиенте или сервере.

## 7. Установка квестов

### 7.1 Каталог

На клиенте и выделенном сервере целевой путь вычисляется через
`FMLPaths.CONFIGDIR`:

```text
config/ftbquests/quests
```

Нельзя записывать в `saves`, каталоги миров, `mods` или `resourcepacks`.

### 7.2 Момент запуска

Проверка выполняется из конструктора главного `@Mod`-класса. В этот момент
Forge уже предоставляет `FMLPaths.CONFIGDIR`, а интегрированный или выделенный
сервер ещё не начал читать книгу.

Отдельный обработчик lifecycle event не нужен. Общая логика не должна
ссылаться на классы из `net.minecraft.client`, чтобы тот же JAR работал на
выделенном сервере.

### 7.3 Manifest

`payload-manifest.json` содержит:

```json
{
  "schemaVersion": 1,
  "translationVersion": "VERSION",
  "modpackVersion": "1.19.3-7-ae2-fix",
  "originalFiles": {
    "data.snbt": "SHA256",
    "chapter_groups.snbt": "SHA256",
    "chapters/example.snbt": "SHA256"
  },
  "translatedFiles": {
    "data.snbt": "SHA256",
    "chapter_groups.snbt": "SHA256",
    "chapters/example.snbt": "SHA256"
  }
}
```

Обе карты содержат полный набор обычных файлов относительно каталога `quests`.
Сравниваются и пути, и SHA-256. Дополнительный, отсутствующий или изменённый
файл делает состояние неизвестным.

### 7.4 Состояния

| Состояние | Действие |
| --- | --- |
| Полное совпадение с `originalFiles` | Создать backup и установить перевод |
| Полное совпадение с `translatedFiles` | Ничего не записывать |
| Каталог отсутствует | Отказаться от установки |
| Любое другое содержимое | Отказаться от установки |

Поддержка обновления старых переводов не входит в первую версию. Для следующего
релиза она добавляется только при появлении реального второго набора входных
данных.

### 7.5 Безопасная замена

Минимальный алгоритм:

1. прочитать и проверить встроенный manifest;
2. вычислить SHA-256 текущего каталога без перехода по символическим ссылкам;
3. отказаться от записи, если каталог не равен поддерживаемому оригиналу;
4. скопировать встроенный перевод во временный каталог внутри
   `config/liminal_industries_ru`;
5. проверить временный каталог по `translatedFiles`;
6. переместить исходный `quests` в
   `config/liminal_industries_ru/backups/<UTC_TIMESTAMP>/quests`;
7. переместить подготовленный каталог на место `quests`;
8. если второй move завершился ошибкой, вернуть backup на исходное место;
9. удалить оставшийся временный каталог.

Временный каталог и цель находятся в одном `config`, поэтому move не пересекает
файловые разделы. Использовать `ATOMIC_MOVE`, когда файловая система его
поддерживает, и обычный `move` как переносимый fallback. Нельзя обещать
абсолютную атомарность каталогов на всех поддерживаемых файловых системах.

Backup не ротируется и не удаляется автоматически. На обычной установке
создаётся один backup; дополнительные механизмы хранения пока не нужны.

Если процесс был принудительно завершён между двумя move, пользователь может
восстановить каталог из последнего backup при остановленной игре. Автоматическая
команда восстановления не входит в MVP.

### 7.6 Проверка путей

Разрешены только относительные пути, перечисленные в manifest. Реализация
отклоняет:

- абсолютные пути;
- пустые сегменты, `.` и `..`;
- символические ссылки;
- файлы, которых нет в соответствующей карте manifest.

Мод не использует сеть, не запускает внешние процессы и не распаковывает
произвольные архивы.

## 8. Клиент и сервер

В одиночной игре клиентский профиль содержит авторитетную книгу для
интегрированного сервера, поэтому установленный каталог применяется при старте
мира.

На выделенном сервере авторитетной является серверная книга FTB Quests. Для её
перевода тот же JAR устанавливается на сервер. При подключении к чужому серверу
локальный мод не изменяет синхронизированные сервером данные.

Языковые ресурсы нужны только клиенту и безвредно игнорируются выделенным
сервером.

## 9. Диагностика

Использовать обычный SLF4J logger с mod id в имени. На каждом запуске достаточно
записать:

- распознанное состояние: `original`, `translated`, `missing` или `unknown`;
- результат проверки встроенного payload;
- путь backup после установки;
- результат: `installed`, `already installed`, `refused` или `failed`;
- исключение и результат восстановления при ошибке move.

Отдельные `state.json`, `last-report.txt` и команды `/liminalru` не требуются.
Та же информация уже доступна в `logs/latest.log`.

## 10. Сборка

Основа проекта: официальный MDK для Minecraft 1.20.1 с ForgeGradle 6.

```sh
cd mod
./gradlew clean test build
```

Артефакт:

```text
mod/build/libs/liminal-industries-russian-translation-<version>.jar
```

Сборка или тесты должны завершаться ошибкой при:

- невалидном или содержащем повторяющиеся ключи языковом JSON;
- отсутствии `data.snbt`, `chapter_groups.snbt` или каталога `chapters`;
- несовпадении встроенных квестов с `translatedFiles`;
- небезопасном пути в manifest.

Не добавлять отдельный framework, DI-контейнер или собственную task-систему.
Для JSON использовать уже доступный в окружении Gson, для SHA-256 и файловых
операций — стандартную библиотеку Java.

## 11. Тестирование MVP

Автоматические тесты покрывают только собственную файловую логику:

1. распознавание оригинала, перевода, отсутствующего и неизвестного каталога;
2. установка оригинала с созданием backup;
3. повторный запуск без записи;
4. отказ при дополнительном, отсутствующем или изменённом файле;
5. восстановление исходного каталога при искусственной ошибке второго move;
6. отказ для небезопасного пути и символической ссылки.

Ручная проверка перед релизом:

1. запуск чистой копии поддерживаемого профиля;
2. проверка перевода названий при выбранном языке `ru_ru`;
3. проверка всех глав в новом одиночном мире;
4. повторный запуск без изменения квестовых файлов;
5. запуск выделенного сервера с JAR;
6. подключение клиента с модом и без него;
7. запуск клиента с модом на сервере без него;
8. проверка сохранения прогресса на копии существующего мира;
9. проверка безопасного отказа после изменения одного SNBT.

## 12. Публикация

Первый CurseForge-файл публикуется как Forge mod для Minecraft 1.20.1 с
окружением client and server. FTB Quests указывается как required dependency.
В описании явно указывается единственная проверенная версия
Liminal Industries - Rescripted: `1.19.3 - 7 (AE2 fix)`.

Пользователь устанавливает оригинальный модпак, затем один раз добавляет JAR
перевода в его профиль. Без доступа к проекту оригинального модпака автоматически
включить перевод в состав модпака нельзя.

До публикации необходимо подтвердить:

- лицензию кода мода;
- право распространять файлы перевода;
- допустимость распространения переведённого текста квестов исходного проекта;
- необходимые атрибуции авторам модпака и переводимых модов.

Пока юридическая проверка не завершена, публичный релиз блокируется.

## 13. Критерии готовности

MVP готов, когда:

1. один JAR устанавливается в поддерживаемый профиль;
2. языковые JSON загружаются из JAR мода;
3. проверенный оригинальный каталог квестов заменяется до запуска сервера;
4. перед заменой создаётся backup;
5. повторный запуск не записывает файлы;
6. неизвестный каталог не изменяется;
7. ошибка move восстанавливает исходный каталог;
8. клиент и выделенный сервер запускаются без ошибок;
9. прогресс сохраняется на тестовой копии мира;
10. `./gradlew clean test build` проходит.

## 14. Вне MVP

- поддержка других версий Minecraft, Forge, FTB Quests или модпака;
- обновление с ранее выпущенной версии перевода;
- команды status и restore;
- GUI и настройка backup;
- автоматическая очистка backup;
- изменение языка Minecraft;
- скачивание обновлений;
- перевод данных чужого сервера на стороне клиента.
